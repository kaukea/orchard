## Blockers

None for the design; execution follows the kaukea/orchard move.

## Questions

- What does the skill DECIDE versus what does the operator? A project with
  its own decision log and task tracker needs judgement calls per artifact:
  convert, coexist, or leave. The operator wonders whether a skill should
  carry that judgement — its shape is the open design.

## Findings

Operator (2026-08-18): existing projects with their OWN decision-making and
task-management processes need migrating into orchard, and how is unsettled
— "a skill might be needed there to decide how to do so." Prior art: the
history-rewrite skill (procedure for main-restructuring, executed verbatim,
gates everywhere) and Decision-144's board transitions (scrub gates, formats
re-judged not translated mechanically).

## Proposal

A skill — working name adopting-orchard — that walks an existing project's
process artifacts (decision logs, task trackers, conventions), proposes per
artifact convert/coexist/leave with the reasoning, and executes only
operator-approved conversions, riding each project's own workflow.

## Testing

To be agreed at design; a real adoption of one own-process project is the
obvious proof.
